# Поддерживаемые мыши и Bluetooth

| Поддержка | Модели | Что работает |
|---|---|---|
| **Проверенный модуль** | Razer Naga Pro: кабель (`1532:008F`) и приёмник HyperSpeed (`1532:0090`) | всё |
| **Семейство Naga Pro**, не проверено | Naga V2 Pro (`00A7`, `00A8`); Naga Pro по Bluetooth (`0092`) | всё, экспериментально |
| **База OpenRazer + проверка памяти** | 68 современных мышей: Basilisk V2/V3, DeathAdder V2/V3, Viper Ultimate, Viper V2/V3, Cobra Pro, Naga X, Naga V2 HyperSpeed, Pro Click… | то, что подтверждает база, плюс кнопки, макросы и профили, если мышь на них отвечает (экспериментально) |
| **База OpenRazer** | более старые мыши | DPI, стадии, частота опроса, батарея, сон, подсветка — что подтверждает база |

Полный список: **Настройки → Поддерживаемые устройства** или `open-rzr-cli devices`.

## Проверка памяти

Современные мыши Razer используют те же команды кнопок, макросов и профилей, что и Naga Pro. При подключении open-rzr спрашивает такую мышь запросами **только на чтение** (назначение левой кнопки, число профилей, список макросов). То, на что она отвечает, включается с пометкой *экспериментально* и подсказкой сначала сделать резервную копию.

Кнопки находятся перебором. Одинаковые у всех мышей Razer (левая, правая, средняя, назад, вперёд, колесо) получают названия и заводские назначения; остальные показываются как *Кнопка 0x..* с тем, что они делают сейчас, и их можно переименовать. На рисунке — только кнопки, которые есть у мыши; у Naga без сменных панелей (Naga X, Left-Handed, V2 HyperSpeed) появляется вид сбоку с 12 клавишами.

## Bluetooth

По Bluetooth LE Naga Pro для системы — другое устройство (номер модели `0092`) с шестью HID-устройствами (мышь, клавиатура, медиа-клавиши, системные клавиши и ещё два). Все они только передают ввод: команды настройки, которые работают по кабелю, ни одно из них не принимает. Канал настроек Naga Pro по Bluetooth — отдельный GATT-сервис производителя (`52401523-…`), через который и работает open-rzr — см. ниже.

- Если одно из них отвечает на команды настройки, мышь настраивается так же, как по кабелю.
- Если нет (Naga Pro), open-rzr подключается через GATT-сервис Razer (Windows). Читаются прошивка, серийный номер, заряд, DPI и стадии, время до сна, яркость подсветки, слоты мыши и назначения кнопок в них, а **менять можно назначения кнопок** (оба слоя, в слотах, которые есть в мыши) и **время до сна**. Остальное по Bluetooth только читается, слоты нельзя создавать и удалять, и временного слоя нет: чтобы использовать профиль, он должен быть в слоте, и его изменения сразу записываются в слот. Для остального подключите мышь кабелем или через приёмник HyperSpeed — настройки остаются в мыши и работают и по Bluetooth.
- Частоты опроса по Bluetooth нет: отчёты идут с интервалом соединения Bluetooth (Naga Pro просит 7,5–11,25 мс, примерно 90–130 Гц), поэтому настройка частоты скрыта. 125/500/1000 Гц относятся к кабелю и приёмнику.

**Диагностика → Беспроводное** (вид страницы «Диагностика» рядом с журналом) показывает для мыши на Bluetooth её HID-устройства с длинами и номерами отчётов, GATT-сервисы и характеристики (читаемые значения читаются — заряд, сведения об устройстве) и умеет делать **пробу** запросом «версия прошивки» (только чтение). Всё пишется и в журнал, так что попадает в *Сохранить отчёт*. **Диагностика → Все HID-устройства** показывает каждое устройство с назначением (★ — от производителя) и типом подключения — полезно, когда мышь не находится.

### Команды Razer по Bluetooth (Windows)

Сервис производителя принимает свои команды — не 90-байтовый отчёт USB:

```text
…1524  запись       запрос [номер, длина, 00, 00, класс, команда, уточн.1, уточн.2] (+ данные «установки» второй записью)
…1525  уведомления  ответ  [номер, длина, 00, 00, 00, 00, 00, статус], затем `длина` байт уведомлениями по 20 байт
```

Статус тот же, что по USB (`02` — успешно, `03` — ошибка, `05` — не поддерживается); числа — от младшего байта к старшему; номера классов и команд свои. Известно на Naga Pro: `00 81` — прошивка, `05 81` (уточнение `00 01`) — заряд, `0b 84` (уточнение `01 00`) — стадии DPI, `10 83` — эффект подсветки, `03 80` — список слотов и `03 82` — активный слот (номера как по USB), `08 83` (уточнение `<слот> 00`) — все назначения слота, `08 84` (уточнение `<слот> <кнопка>`) — одно назначение (слот `00` — активный, только чтение).

Запись: назначение кнопки — `08 04` (уточнение `<слот> <кнопка>`) с данными `<слот> <кнопка> <слой> <действие, 7 байт>` (слой `00` — обычный, `01` — Hypershift); этот формат нашёл проект OpenSnek на мышах Basilisk. Время до сна — `05 04` с числом секунд. **Диагностика → Беспроводное → Самопроверка записи** проверяет оба на вашей мыши, а также сохраняется ли назначение после выключения мыши.

- **Прочитать известное** — спрашивает эти четыре команды и показывает, что они значат.
- **Класс / Команда / Уточнение → Прочитать** — один запрос.
- **Перебрать команды** — все классы × команды × уточнения из заданных диапазонов (например, классы `00-1f`, команды `80-9f`). Отправляются только команды чтения (команда `80`–`FF`): в мыши ничего не меняется. Ответы «не поддерживается» скрыты, если не снять галочку.

**GATT-канал Razer** ниже: подписывается на уведомления, записывает введённые байты (или только слушает) и показывает каждое уведомление со временем — для разбора остального протокола. После этого отправьте отчёт.

## Другая мышь

Если ваша мышь отмечена как *экспериментальная* и что-то работает неправильно, пришлите отчёт из **Диагностика → Сохранить отчёт**. Полноценный модуль новой модели (названия, рисунок, заводские назначения) начинается с копии `crates/rzr-devices/src/naga_pro.rs`.

## Файлы устройств

Модель, которой нет в списке (или у которой запись не совсем верна), можно описать файлом, без пересборки. Положите по одному `*.toml` (или `*.json`) на устройство в папку **devices**: **Диагностика → Файлы устройств** показывает папку, перечитывает её и выводит ошибки. В Windows это `%APPDATA%\open-rzr\devices`, в Linux — `~/.config/open-rzr/devices`.

Файл берёт за основу запись базы OpenRazer с тем же product id (или модель из `base_pid`, например `0x008F` для «родственника» Naga Pro) и меняет только то, что в нём указано:

```toml
pid = 0x00AB                    # product id (Диспетчер устройств / lsusb: 1532:00ab)
name = "Razer Example Mouse"
# base_pid = 0x008F             # основа — известная модель, а не запись OpenRazer
transaction_id = 0x1F
wireless = false
battery = false
max_dpi = 26000
dpi_stages = 5
features = ["firmware", "serial", "dpi", "dpi_stages", "polling", "lighting"]

[[zones]]
id = "logo"                     # scroll, logo, side, left, right, backlight
led = 0x04
effects = ["off", "static", "spectrum", "breath"]

[[buttons]]
id = 0x60
name = "DPI down"
```

Функции: firmware, serial, dpi, dpi_stages, polling, battery, charging, idle, low_battery, lighting, buttons, macros, profiles, side_plate. Эффекты: off, static, spectrum, wave, breath, reactive, custom. Неизвестные ключи и названия выводятся как предупреждения. Проверенный модуль (Naga Pro) не заменяется, если в файле нет `override = true`. Модели из файлов помечаются как *ваш файл* и считаются экспериментальными. В командной строке то же самое: `open-rzr-cli device-files`.
